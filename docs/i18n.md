# Translations (i18n)

The client uses [i18next](https://www.i18next.com/) with [react-i18next](https://react.i18next.com/). Text is in JSON catalogs, one folder per domain: `packages/client-react/src/<domain>/locales/<language>.json`. The domain is the i18next namespace (`shared`, `user`; `game` and the lobby follow). English (`en`) is the source language and ships in the main bundle. Every other language is a separate chunk that loads when it is chosen.

## Using a string

```tsx
const { t } = useTranslation('user')   // `shared` is the default namespace
<label>{t('auth.username')}</label>
```

Keys are typed from `en.json`: a wrong key fails `npm run type-check`. Outside React (a class component, a utility) use `i18n.t('errors.unexpected')` from `@/shared/i18n`. In `shared/`, `user/` and `App.tsx` ESLint rejects a literal string in JSX text or in an attribute such as `aria-label` (`i18next/no-literal-string`). Text that comes from the server is not translated yet: it needs error codes first.

Formatting and plurals use the platform's `Intl` through i18next:

```json
{ "players_one": "{{count}} player", "players_other": "{{count}} players", "since": "Since {{date, datetime}}" }
```

## Adding a key

Add it to the domain's `en.json` with a semantic name (`auth.switchToRegister`, not `auth.text3`) and use it. Types follow on their own.

## Adding a language

1. In each domain that has strings, copy `locales/en.json` to `locales/<language>.json` (for example `de.json`) and translate the values. Keep every key and every `{{placeholder}}`. Plural keys follow the language's [CLDR plural categories](https://cldr.unicode.org/index/cldr-spec/plural-rules): German uses `_one` and `_other`, Russian also `_few` and `_many`.
2. Nothing else is needed. The language shows up in the switcher under its own name (from `Intl.DisplayNames`), is picked from the browser's languages on a first visit, and is remembered in `localStorage` (`santorini.language`). A key a language lacks falls back to English.
3. `npm test` checks that the new file has the keys and placeholders of `en.json`. The switcher is hidden while only one language exists.

## The pseudo-locale

Development builds (`npm run dev`, the e2e suite) also offer `en-XA`, generated from the English catalogs by `pseudoLocalize`: every letter is accented, the text is about 30% longer and wrapped in brackets. Switch to it and look at a page: text that is not accented and bracketed is hard-coded, and a bracket that is cut off marks a layout that cannot take longer translations. It is not in production builds.

## Not covered yet

- The game views, the lobby and the debug tools still contain literal English text.
- Strings the server sends (REST error bodies, WebSocket `error` messages) reach the screen as they are.
- `index.html` has a static English `<noscript>` text and a static English title and description until the app starts; after that they follow the language.
